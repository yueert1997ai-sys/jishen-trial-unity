# 《机神试炼》核心玩法约定

确认日期：2026-09-06。本文记录已与用户确认的下一阶段设计，作为后续迭代依据；不代表这些系统已经实现。本次只更新文档。

## 核心体验

驾驶固定本体的机甲，在节奏明快的战斗中夺取敌方武器与背包，永久收藏，再用局内随机强化放大自己选择的战斗方式。

核心循环：看见想要的装备 → 击败持有它的敌人 → 吸收并收藏 → 选择试用或保留当前装备 → 继续战斗。

## 已确认的规则

| 项目 | 约定 |
| --- | --- |
| 主角本体 | 保持固定。第一阶段只围绕武器和背包做装备变化，其他身体部件留到后续迭代。 |
| 武器与背包 | 获得后永久进入仓库，单局结束不清空。主要价值是功能与战斗方式，外观体现装备差异。 |
| 装备选择 | 获得装备不自动替换当前装备。玩家可以一直使用喜欢的装备，不强制换装或强化。 |
| 局内 buff | 随机获取，仅在本局生效；本局结束清空，不进入仓库，不跨局继承。 |
| buff 内容 | 先做数值与对应表现增强，例如攻击范围、攻击速度、冷却和爆炸范围；效果的视觉变化应与实际作用对应。 |
| 基础打法 | 由武器和背包决定，局内 buff 在此基础上形成当局的成长与选择。 |

## 单局流程与换装

采用初版提出的短战斗区域结构：出击 → 战斗 → 清场后的随机强化选择与装备整理 → 下一战斗区域 → Boss → 结算。

- 出击前可从永久仓库选择装备。
- 战斗区域之间可整理、替换装备。本场获得的新装备可在清场后装备，本局即可使用。
- 清场提供随机 buff 选择，让玩家围绕当前打法取舍。本轮不预设固定 buff 路线。
- 本局结束后保留已获得的武器、背包，清除本局 buff。
- 操作追求快速响应、明确命中反馈和连贯移动；换装与成长界面集中在战斗间隙。

## 吸收的表现方向

主角伸手，敌方残骸上的可回收部件被牵引过来，伴随核心响应和收纳／重构表现，完成装备获取。需要让玩家清楚感到自己拿到了刚才敌人在使用的东西。

吸收负责获取，是否装备由玩家决定。完整的仪式动画放在后续制作，不作为第一轮玩法预览的前置条件。首次获取与重复获取是否使用不同长度的表现，留待预览后确定。

实现时优先采用预先制作、可分离的武器与背包模块，让敌我复用同一装备资产；运行时生成新模型不属于首版需求。

## 第一轮玩法预览的范围

先打通一条可玩的完整循环：从敌人获得装备 → 仓库保留 → 选择装备并使用 → 获得随机 buff → 结束本局 → 再次出击时装备仍在、buff 已清空。

先提供足以感受武器与背包功能差异的少量内容，具体数量和名单在实现前确定。暂不扩展全身拼装、复杂元素反应、装备词条经济或完整吸收演出。

预览以能运行、装备变化可见、基本战斗与保存／重置规则可体验为准，默认快速检查，不做长时间回放或全面视觉审计。

## 尚未确定与现有项目的关系

重复装备如何处理、具体掉落规则、装备槽数量、首批装备和 buff 数值、关卡数量，均未在本轮定案。

现有原型的操作、关卡和临时强化可作为迭代基础；永久装备仓库、敌方装备获取及上述流程需要后续实际开发。历史计划中与本文冲突的未来玩法限制，以本文为准。本文不要求重做项目，也不授权改动由另一进程处理的主角模型源文件。
