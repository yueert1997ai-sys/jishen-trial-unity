## 发给玩家的开场白

这次想了解你刚才实际怎么玩、在哪一刻想继续或不想继续。没有标准答案，不需要懂游戏设计，也不用提出解决方案。觉得无聊、没感觉、说不清都可以直接写。

请自然玩一局，想停就停，不用为了填问卷硬打通。填答约 3–5 分钟。没体验到的内容选“未体验”，不要猜。

试玩操作：WASD 移动，自动瞄准射击，空格冲刺，E 发射导弹，1/2/3 选择强化，Esc 暂停。首次建议 DEMO 难度。

## 仅供开发者：怎么最快用这份问卷

### 第一轮怎么测

- 先找 5 位潜在玩家作为一轮快速定性测试的起点，分别记录是否常玩同类游戏。人数是工作安排，不是统计充分性的保证。开发者自己的回答单列，不混作外部玩家结论。
- 同一轮使用同一版本，首次玩家默认 DEMO；改难度的人单独看。记录构建号、设备、操作方式和声音是否开启。Windows 键盘结果不能代替手机触控结论。
- 玩家试玩前只看开场白与操作说明；不要先展示第 5–10 题，也不要告诉他们“我觉得不爽”。先收自由描述，再给诊断选项，减少提示答案。
- 自然玩至通关或主动停止，预计完整流程约 10–15 分钟；提前停止本身就是证据。不要强迫打到 Boss。
- 如玩家同意观察或录屏，记录首次主动使用冲刺/导弹、第一次强化、第一次明显受伤、第一次走神/停玩。区分玩家原话和你的解释；不要把推测写成玩家事实。
- 填完只追问一件事：“能指出刚才发生这件事的那一段吗？”有具体片段再问“你当时想做什么，实际发生了什么？”

### 回答怎样转成下一轮改动

以下是待验证假设，不是根据代码已经确诊的问题。每次只选一个主要假设做小改版。

| 多条证据同时出现时 | 优先检查的假设 | 最小验证方向 |
| --- | --- | --- |
| 走位影响评分低；导弹冷却好就按；主动操作是首选改动 | 玩家缺少有意义的时机决策 | 给现有导弹创造一个清晰的使用时机，比较玩家是否开始主动等待/选择时机 |
| 能看懂命中但不满足；首选命中反馈 | 命中和击毁反馈偏弱 | 保持伤害不变，仅比较一组命中音效与击毁反馈 |
| 冲刺不好控；可指出撞建筑或停不准的片段 | 位移曲线、碰撞或空间读图影响控制 | 针对片段只调一项，例如冲刺减速曲线或一处障碍位置 |
| 自动选敌评分低；掩体常挡枪；玩家频繁为目标绕路 | 锁敌和视线规则与意图不一致 | 复现该位置，检查目标切换与遮挡提示，再改一个规则 |
| 第一次走神发生在强化前；战斗重复；首选节奏 | 有效事件间隔过长 | 缩短一段空档或替换一段重复增援，对比同一阶段 |
| 强化选项随便选/差不多；变化评分低；首选成长 | 强化理解或效果区分不足 | 看不懂先改卡片说明；看懂没感觉再放大一项现有强化的实际差异 |
| 死亡原因不明；Boss 看不懂；首选可读性 | 攻击信息传达不足 | 先改一种攻击的预警与受伤提示，保持伤害不变 |
| 知道怎么应对但做不到；首选降低难度 | 容错或压力偏高 | 只调整一个压力来源，例如同屏远程敌人上限 |
| 期待重型机甲操作，实际像自动射击绕圈 | 产品承诺与核心玩法可能不匹配 | 先明确目标玩家偏好，再决定是否做独立的主动攻击小原型；不能仅据单条意见上完整近战系统 |

### 排序与复测

1. 阻断游玩或造成明显错误的故障先处理。
2. 其余优先看：与主动停玩/不想重开同时出现、有具体片段、被多名玩家独立提到的问题。第 9 题投票只作辅助，不能直接当功能需求单。
3. 分别统计每个问题“几人遇到 / 几人实际体验了该环节”。Boss、强化没体验的人排除出该题分母；小样本写人数，不把百分比当总体结论。不把矩阵平均成一个“爽感总分”。
4. 每轮写一句：因为 __ 名玩家在 __ 时出现 __，我们怀疑 __；这次只改 __；若有效，应看到 __。
5. 改完优先复测第 2 题、对应维度和原问题片段；观察玩家是否实际选择重开，单独记录“口头想重开”和“真的重开”。
6. 条件允许时用两个短版本对比，交替试玩顺序，尽量匹配难度和强化路线，避免把熟练度或随机卡片差异误当改进效果。评分提高但具体问题仍发生，不能算解决。
