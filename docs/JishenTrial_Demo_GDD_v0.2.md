## 4. 核心循环

### 4.1 数秒内的战斗循环

**识别威胁 → 闪避/推进改变距离 → 枪或刀攻击 → 敌人有清楚的反应与击破 → 立刻切向下一个目标。**

枪刀切换提供效率和应对选择，不设置固定考题式连招。无甲小兵不需要先吃炮才能砍。玩家选择目标、出手时机与位移方向，就是这一层的决策。

### 4.2 一两分钟内的夺取循环

**遇见有特色的装备携带者 → 躲过它的攻击并击败 → F 牵引到手 → 装配锁定 → 用同类攻击处理下一组敌人。**

本次特色集中在“敌人使用什么，我拿到后就能做类似的事”。敌人的武器不能只有展示用途；回收后也不能变成与原来完全无关的能力。

### 4.3 整局循环

机库确认搭配 → 六场战斗与简短间歇 → 少量随机强化 → 液态 Boss → 胜负结算。

新收藏跨局保留，buff 本局结束清空。已有永久仓库继续使用，但本次不围绕它扩展长期养成。通关可重玩，不承诺长线刷装寿命。

### 4.4 连续击破的轻量支持

**实施方案：**沿用现有推进能量，击破普通敌人回复少量能量，以支持向下一个目标连续推进。不另加击杀资源条、不设连杀倍数，不要求玩家为维持加成强迫赶路。

试验初值：能量上限按 100 归一化；一次冲刺消耗 25；普通击破回复 10。只有真实敌方死亡事件结算一次；训练靶、重复死亡事件和测试强制清场不发正常奖励。Boss 不靠单次击杀回能维持战斗，基础自然回复必须足够。

## 5. 操作、机动与闪避

### 5.1 默认操作

| 输入 | 规则 |
| --- | --- |
| WASD | 平面移动；移动方向与瞄准方向独立 |
| 鼠标 | 手动瞄准，保持原有指向意图，不做自动掉头追怪 |
| 左键 | 主射击，按住连续开火；近战状态按规则快速收刀后射击 |
| 右键 / Q | 三段斩击，最多缓存下一段；从射击状态快速拔刀 |
| Space 点按 | 短促闪击，兼具切入、脱离、闪避 |
| Space 按住 | 保留持续低空推进，明确与点按区分 |
| E | 沿用已有固定重火力技能入口，背包固定；不额外叠加第二套大招系统 |
| F | 对明确选中的新掉落执行主动牵引与装配 |
| Esc | 暂停/恢复；清除容易导致误触的待执行输入 |

### 5.2 短促闪击

启动要快，位移方向可预期，停止不能拖泥带水。方向优先级：当前移动输入 > 当前瞄准朝向。不能因为模型朝向、自动瞄准与输入来源争抢造成反向冲刺。

无敌只在短促闪击规定时间内有效，持续推进不保持无敌。残影不拥有受击碰撞体，不能把渲染高度当作永久免伤。墙和战区边界始终有效。

**动作取消规则：**冲刺可以取消挥刀，并清掉未执行的下一刀。取消前尚未出现的命中不能补发；已经命中的目标不能因取消再结算。能量不足时要有短促反馈，不能表现为按键毫无反应。

### 5.3 持续推进

持续推进提供横跨战场、调整角度、追击与退场，不增加独立空战关卡。高速下允许主射击；挥刀按已有平面刀路结算，动作与碰撞投影必须一致。

优先通过更明确的启动脉冲、倾身、喷口方向、地面参照与声音建立区别。喷焰和残影服务方向判断，不遮住弹道。

### 5.4 第一轮试验参数

先抓取实际场景、Prefab、运行时数值，避免只改脚本默认字段。

| 参数 | 试验范围/初值 | 验证重点 |
| --- | --- | --- |
| 推进速度倍率 | 基线 1.32，对比 1.6 与 1.9 | 是否明显更快且仍能转向、识别敌人、避免撞边界 |
| 单次闪击时间 | 约 0.18—0.22s | 启动清楚，短而有力，不像传送 |
| 单次闪击距离 | 约 2—2.5 个机体高度 | 既能越过危险，也不轻易冲出屏幕 |
| 闪击无敌窗口 | 先保留现有 0.16s 做基线 | 预警和实际命中时刻是否对应 |
| 连续闪击间隔 | 对比实际基线与 0.35—0.45s | 能量成为主要约束，不做无限无敌 |
| 能量回复 | 停止推进后短延迟再回复 | 有紧张感但不出现频繁原地等能量 |

以上不得同时无记录地全部替换。先测视野，再测移动，再测战斗组合，并保留组合后的完整复测。

## 6. 镜头与速度感

### 6.1 不先改视角类型

保留固定俯视/斜俯视战斗，不为了接近 AC6 重做第三人称、锁定系统和空间战斗。AC6 是机动体验参考，不是本 Demo 要复刻的整套系统。[S11]

当前是正交镜头。相机离角色更远不直接扩大正交画面的可见范围，调整对象应是 `orthographicSize`、俯角、前瞻和跟随。单纯拉大视野还可能使屏幕中的位移显得更慢，因此视野与机动必须联合测试。

### 6.2 可读性标准

正常战斗能同时看到：玩家、正前方的目标、主要危险预警，以及一次闪击大致会到达的位置。角色不能为了展示模型细节占据过多屏幕。

造型近景放在机库或录像补镜中。实战保持稳定构图，不在每次击杀、普通冲刺、普通命中时推近镜头。

### 6.3 三组对照

固定敌群与同一输入路线，录制：A 当前镜头；B 视野扩大约 15%；C 视野扩大约 25%。这里的百分比作用于正交尺寸，实际地面覆盖受俯角影响。

第一轮保持其他参数一致，判断威胁可见性与目标辨认。选出可读版本后再调整推进速度和前瞻，不能把“看得更远”和“感觉更快”混成一个指标。

移动前瞻按速度适度增加，范围先在 1.25—2.5 米比较，并受视野/战区边界约束。主射击允许少量瞄准前瞻，但不能让朝向快速切换时镜头甩动。默认不加入强运动模糊、长尾镜头滞后或每次冲刺的急剧缩放。

## 7. 枪刀动作与打击规则

### 7.1 近战

保留现有三段顺序与已制作的机体、刀和姿态资产。优化重点为：起手能读懂、有效刀路干净、身体发力与脚步一致、收招能接下一行动。

不通过每段都更慢、更大幅度来追求重量。第一刀起手利落，第二刀反向衔接，第三刀强调更强位移、命中与击破。前两段留出连续性，重反馈集中在第三段或击杀。

**试验初值：**第一刀首次接触约 0.14—0.18s，第二刀约 0.18—0.22s，第三刀约 0.24—0.30s；实际需要先核对刀刃扫掠与现有姿态后重定时。攻击缓存约 0.12—0.18s，最多一段。

普通近战命中停顿先对比 0.03—0.045s，第三刀/高价值击破约 0.055—0.075s。普通射击不使用持续全局停顿。同一刀多目标不能逐个叠加停顿到整场不断卡住。长帧条件下刀尖扫掠、墙体遮挡、同刀去重继续保留。

### 7.2 主射击

射击的价值为可控、连续、便于处理远处威胁，允许边移动边打。命中应有短促的金属反馈与身体反应，但不让普通连射永久硬直敌人。

两种远程打法需要在射速、目标处理方式、反馈节奏上区分。武器切换时不要通过额外菜单打断战斗，也不设置强制“枪积攒资源，刀才能伤害”的基础门槛。

### 7.3 基础击杀时间目标

先用零 buff、固定搭配测试：普通近身杂兵应在一至两次有效刀击内被击破；单个普通远程威胁应能被一次短射击处理。重装携带者与 Boss 单独调节，不把所有杂兵加血来凑时长。

这些是体验目标。实际生命与伤害组合由打样确定，不直接套用旧仓库数值。

| 主射击 | M7、M14 | 作为两种主射击候选/变体，优先选择已在玩法分支可运行的步枪完成第一轮；另一种用于夺取后的明确对照 |
| 重火力 | FAZZ 炮、蓝色激光炮 | 作为现有 E 技能位的重火力视觉与玩法候选，后续接入替代原表现，不再增加一个新按键或新养成栏 |
| 背包 | 当前主角背包 | 固定，只为机动与技能提供挂点，不开放更换 |

**当前打样配置固定：一把已可用步枪＋当前斩舰刀＋一个现有 E 技能。** 第一条 F 夺取链使用另一把主射击武器，作为策划工作默认，名称以分支资产核验为准。M7/M14 在另一分支存在，不等于已经能在玩法分支无成本使用；必须完成引用、双手持握、炮口和攻击规则检查。

本轮先验证现有资产能支撑的核心动作。重炮最终用哪个外观、两门是否均展示，不阻塞打样，也不得以此启动新的模型重做或完整双重炮系统。

## 9. F 牵引与装配

### 9.1 本轮对既有约定的更新

原约定允许清场后换装，获取不强制自动装备。本轮用户强调 F 吸到手并装上的仪式感。

**实施方案：F 本身就是玩家主动选择“吸收并试装这件”的明确操作。** 它是战斗中对新掉落的有限例外，不代表开放战斗背包和任意换装。忽略掉落可继续用原装备；主动离开区域时，未试装的新武器只收藏，不自动顶掉当前武器。

### 9.2 目标选择与触发

新武器以实际独立模块留在残骸上或旁边，带清楚的形状与短名称。玩家在可交互距离内、无遮挡且目标明确时显示“F 牵引装配”。推荐试验距离约 5—6 米，再根据实际镜头调整。

同时有多个掉落时，优先瞄准方向更接近的目标，再比较距离，并高亮最终目标；按 F 只处理一个。不能沿用全范围批量吸收，把数件武器同时拉到同一只手上。

### 9.3 一次完整表现

首次展示目标约 0.8—1.1 秒，不切长过场：

| 阶段 | 目标时段 | 画面/声音 | 规则 |
| --- | --- | --- | --- |
| 锁定牵引 | 0—0.15s | 主角抬手，核心/接口响应，短促牵引启动声 | 校验可获取与可安装，预留唯一目标 |
| 模块飞来 | 0.15—0.50s | 残骸上的原武器沿明确轨迹飞向手部 | 使用原装备资产，不变成无关光球 |
| 接住与锁定 | 0.50—0.85s | 手臂短促承重，接口对齐，机械锁扣声 | 新旧武器实例与挂点原子替换 |
| 就绪 | 0.85—1.05s | 能量通道点亮、短就绪声、武器名淡出 | 恢复攻击，用新配置实际发射 |

完整时间是试验初值。已拥有的同型装备不反复触发长演出，也不刷出一地相同掉落。

### 9.4 快速战斗与仪式感如何兼容

首个指定携带者安排为该区域最后一个重要目标，使玩家能在安全情况下体验完整装配。后续装配不强制推近相机、不锁住整个世界。

装配期间可以用闪击取消后半段。取消不抹除已经获得的收藏，不在安装未完成时发射新武器；旧武器继续有效。受击本身正常结算，死亡结束动作。取消后该收藏标为待试装，可在清场时再次进行短装配；不用再杀一次敌人获取。

不为吸收额外引入无敌时间、吸收资源或 QTE。最初只需一件新武器的一次完整仪式，避免演出工作量变成所有资产全套动作工程。

### 9.5 所有权、存档与换装规则

吸收事务与视觉动画分开。确认获取成功并完成持久化后才正式移除可再次获取状态；同一 pickup/装备 ID 只处理一次。保存失败不得假装成功，保留可重试提示。

旧武器仍在永久仓库，不销毁所有权、不掉到地上。新武器占相同功能位，不替换近战和固定背包。安装成功不重置玩家耐久、不清掉局内 buff；属性从基础配置与当前 buff 重新计算，禁止重复乘加。

死亡或重开保留已成功写入的装备；buff 不跨局保留。装配被取消或死亡后，不能继续触发延迟开火、音效、挂点更新。

### 9.6 清场流程必须改序

**清场 → 展示新残骸及 F 提示 → 玩家试装或选择离开 → 未试装部件只收藏 → 三选一强化 → 下一场。**

不能在最后一名敌人死亡的同一帧自动吸走主展示武器、弹出强化界面，导致用户根本没有按 F 的机会。普通已收集物可以自动清理，不阻塞继续。

## 10. 敌人、受击与敌群

### 10.1 第一阶段只使用三种行为职责

模型优先复用现有白兵与已完成资产。行为可以区分，未必要再造三台完整新机体。

| 职责 | 行为 | 玩家决策 |
| --- | --- | --- |
| 追击型 | 接近但不无限挤在同一点，预警后突击，落空后短暂暴露 | 横移、闪击绕侧、近战连斩 |
| 步枪型 | 保持中距离，短连射后重定位；不要每个射手永远同一帧瞄同一点 | 先处理交叉火力或高速切入 |
| 武器携带者 | 展示即将掉落的武器；攻击前有可读准备，之后有短恢复 | 观察该武器特点，击破后回收 |

最终 Boss 沿用液态侵蚀体及已有阶段，不在此额外增加正式 Boss。

### 10.2 受击是战斗结果，不只是闪白

普通命中必须同时具备可见接触、金属/能量反馈和对应身体反应。轻枪击可做局部反冲，不必每发打断；近战有效斩击给予轻型敌人短硬直；第三刀/重火力给予更明显击退或失衡。

受击状态必须与行为一致：处于允许打断的硬直中不能继续无缝开火；已经完成发射的弹体不因敌人被打而自动消失。短暂硬直设置重复保护，避免高速枪械把所有敌人永久钉住。

Boss 对普通攻击仍要有受击提示，但不因每发子弹中断大招。重型敌人的特殊攻击若不可被轻击打断，要靠姿态、音色或预警表现这种差异，不靠玩家猜。

死亡当帧关闭攻击与伤害生成，保留短促机械崩解或倒地。死亡模型、武器残骸与拾取逻辑分开，不能因为销毁尸体把待回收装备一起删除。

### 10.3 敌群编排

同屏先控制约 6—10 个有效敌人，以清晰行为和可读目标为主。限制高威胁攻击同时启动数量，避免三个攻击在同一瞬间无缝覆盖全部落点。不是全部排队挨打，而是交替制造可处理的压力。

不以持续刷数百只同质白兵来证明战斗充实。每场最多引入一个新压力，组合后再重复；击破速度快时，增援应自然接续，不强迫玩家等满旧时间轴。

## 11. 美术、特效、音效的最低完成标准

### 11.1 动作

逐条检查起手、关键接触、结束三个时刻。武器握点稳定；手臂、腰胯、脚步共享发力方向；收刀与开火不重叠穿帮。挥刀不从空气命中，枪弹不从旧肩炮口冒出。

保留模型本身细节，战斗镜头按可读性取舍。近景穿插和正常游戏镜头分别检查，近景好看不能证明战斗中看得清。

### 11.2 反馈分级

| 事件 | 表现重点 |
| --- | --- |
| 普通射击 | 干净短促的开火与命中，轻局部反应，不使用强镜头震动 |
| 近战前两刀 | 不同方向的刀路、金属接触、短停顿 |
| 第三刀/重火力 | 更强低频、较明显击退、短而克制的镜头冲击 |
| 闪击 | 启动脉冲、方向清楚的光翼/残影、收束声 |
| 吸收装配 | 牵引、接住重量、机械扣合、启动完成四个信息点 |
| Boss 终结 | 一次足够明确的击破与结束收束，不用每次小兵死亡都复用 |

光翼残影不能延迟显示玩家真实位置，镜头抖动和闪光均应可关闭。关掉特效后动作仍应成立，开回特效后危险预警仍应可辨。

### 11.3 音效重新验收

当前声音已被用户明确否定，不能因为文件齐全、峰值不过载就保留为已完成项。

先只重做五组：主枪、斩舰刀、闪击推进、敌方受击/死亡、F 装配。先在武器试场静音背景音乐试听，再带回战斗混音。每组保留少量方案，由用户听真实游戏录音比较；不一次采购、生成或拼接几十个新声音。

斩舰刀需要空挥、切中装甲、重劈的音色和力度差异。推进需要短促有力的启动与可辨持续层，不能靠刺耳高频表现快。F 最重要的是接住与锁扣瞬间，不能只有泛用奖励铃声。

来源与许可记录到项目现有资产文档；自制、AI 合成、第三方样本分别标记。无来源的商业游戏音频不进入交付包。程序检查只验触发时机、堆叠、暂停清理、音量上限；用户耳听是音色验收的必要条件。

## 12. 局内强化：六种，先服务基础动作

由策划收口为六种，均为本局有效。没有新技能树、稀有度、三系羁绊或独立大招槽。

| ID | 名称 | 每级效果试验初值 | 表现/边界 |
| --- | --- | --- | --- |
| `blade_reach` | 延展刃场 | 刀刃有效范围 +10% | 有效光刃与判定同步扩展，不让实体手臂拉长 |
| `blade_drive` | 伺服加速 | 刀击整体节奏快 8% | 动作、命中、声音同步重定时；与射速分开 |
| `fire_rate` | 火控提速 | 主射击频率 +10% | 枪口与后坐频率对应，不能只改面板 |
| `penetration` | 贯穿校准 | 主射击额外贯穿 1 个目标 | 墙体照常阻挡；基础已贯穿时继续按总上限处理 |
| `thruster_efficiency` | 推进效率 | 闪击与持续推进消耗降低 10% | 不增加无敌窗口、不消除全部机动限制 |
| `heavy_reload` | 重火力回转 | E 技能冷却降低 10% | 不新增技能、不改变固定背包规则 |

统一最多 3 级，效果按基础值加算后一次应用。例如三级推进效率为基础消耗乘 0.7，不反复乘 0.9。最终数值在零 buff 手感通过后才校准。

每次清场随机三选一，共六次选择；同一张卡内不重复；满级条目移出池。当前携带枪刀与固定技能，因此大部分选项有效；未开放功能或不适用的强化必须过滤。任何一次至少给出两项对当前真实可用动作有帮助的选择。

换武器保留当前强化，不保留旧武器导致的重复属性。已有旧强化存量不强行并入新表：先建立独立测试配置，确认后统一生效来源。永久仓库绝不写入 buff 等级或当局随机种子。

## 13. 六场与 Boss 的流程

流程数量已确认，以下分工为实施方案；优先复用两个战区，不制作六张全新美术地图。

| 场次 | 主要体验 | 内容与奖励安排 |
| --- | --- | --- |
| 1 | 学会移动、闪避、射击与刀击，迅速有击破反馈 | 少量追击/步枪敌人；指引短而可跳过 |
| 2 | 看见新武器，完成首次 F 夺取装配 | 指定携带者最后出现；装上后给可立即检验差异的目标/下一组 |
| 3 | 混合敌群，验证枪刀取舍 | 不再新增机制；通过距离和敌群站位产生变化 |
| 4 | 更开阔的高速侧向机动 | 延用第二战区，让横移、切入、撤离都有空间 |
| 5 | 强化后再次应对熟悉威胁 | 让相同敌人被更利落地处理，体现当局成长 |
| 6 | Boss 前综合战 | 强调预警、重火力窗口与连续击破，不做大量磨血 |
| Boss | 全流程收束 | 沿用液态 Boss 与已有两阶段，突出可读攻击窗口和终结反馈 |

每场普通战斗先按约 45—75 秒组织；Boss 约 1—2 分钟；加上装备、强化、机库、结算，完整初次体验目标约 8—12 分钟。这是调校目标，不是强制等待时间。熟练玩家更快通关可以接受。

地图需要给至少一次完整闪击留出有效落点，减少装饰小障碍阻挡连贯机动。地板分区、栏杆、灯带和结构参照用于传达位移，避免空白地面导致速度缺乏参照。

六场结束有六次强化，但不得在还未完成 F 演出时抢先弹卡。强化/整备中的等待不计为“战斗内容充实”。

## 14. Boss、胜负与重玩

保留当前液态 Boss，只在已有招式上优化前摇、锁定停止时机、有效命中范围、受击与死亡表现。高速玩家需要可预测的追踪规则，不能在攻击最后一帧无限旋转追准玩家。

Boss 出招后提供足够窗口让玩家快速切入或开重火力；二阶段只加强已有组合和节奏，不再临时增加新阶段、巨型变形与额外演出。

**本稿默认通关即结束。** 展示用时、击破、回收装备和简短完成信息，允许返回机库/重玩。暂不增加 Boss 专属掉落。将来已有武器全部验收后，可以把其中一件作为首通解锁，但不因此新增资产需求。

失败后保留已成功收藏的装备，清除局内强化，允许快速重开。沿用装备分支的统一规则，不能把旧版带 buff 的失败续关不加核查地混回。演示直达 Boss/试场入口与正式流程区别标记，不能把受保护的专项测试录成自然通关证据。

## 15. 界面与信息优先级

战斗 HUD 主要显示：耐久、已有推进能量、主武器与 E 状态、当前目标/阶段、必要 Boss 信息。暂不新增连杀表、装备品质、货币、角色等级等展示项。

F 提示要能看清将获取与将安装的具体武器；装配完成短显示武器名，随后归位，避免遮住下一个敌人。

暂停、强化、仓库、装配与结算只能有一个明确的输入所有者。打开界面清除持续射击和缓存斩击，退出后不得自动执行残留攻击。相机近景只在安全展示阶段出现，不能影响正式瞄准与碰撞坐标。

## 16. 实现边界与最小架构调整

优先沿用现有组件，不引入新的通用战斗框架。

| 责任 | 应落在何处 | 禁止的混用 |
| --- | --- | --- |
| 移动/闪击/推进 | `PlayerController` 与现有输入/属性 | 用视觉喷焰或模型局部坐标驱动真实伤害免疫 |
| 刀击规则与刀路 | 现有近战、姿态、刀刃扫掠组件 | 动画事件、特效和伤害各自独立计时 |
| 镜头 | `CameraFollow` 或其集中配置 | 普通、Boss、F 演出三个脚本同时改相机 |
| 敌人受击和 AI | 敌人状态与伤害事件协作 | 视觉显示硬直但协程继续无条件开火 |
| 收藏 | 现有 `SalvageWarehouse` | 动画没播完就认为存档不需要处理，或把 buff 写入永久档 |
| F 装配 | 在现有装备循环中增加小型事务/状态模块 | 把战斗中任意打开仓库当成仪式感实现 |
| 强化 | 统一当局属性入口 | 新旧装备与 buff 反复叠加造成数值漂移 |
| 音效 | 现有音频事件与声音库 | 普通命中/吸收/技能共用一个泛用声音并只改音量 |

F 状态可用 `Idle → Pulling → Attaching → Ready`，失败/取消明确回到稳定状态，不必建立大型装备动画框架。保存提交、视觉完成和战斗配置应用需分别记录。

旧档中已经拥有的背包装备不删除，保存兼容仍可读取；本 Demo 固定应用指定背包，隐藏背包选择与新掉落，防止老存档偷偷带来额外属性。

不要运行会覆盖场景的旧生成器，不降级工程版本，不覆盖另一工作区的 Blender 主文件。资产接入使用冻结副本、稳定 ID、必要 `.meta` 与来源清单。

## 17. 实施顺序与停止条件

### P0：只做一个 60—90 秒的代表性战斗片段

配置固定为当前可用枪、斩舰刀、固定背包/技能；不接新养成。片段只包括几组明确敌人、一名指定携带者和一件可 F 装配的装备。

先完成镜头基线与视野比较，再优化闪击/推进与取消，再打磨刀枪命中、敌人反应和五组核心声音，最后把 F 完整链路接入同一片段。

**P0 通过条件：**用户愿意主动重复玩，能说出位移、命中、音效和夺取各自哪里改善；零 buff 时仍有连续击破的乐趣。若没有通过，不扩展六场、不增加武器种类。

### P1：复用打样到完整流程

把经过确认的机动、镜头、敌人反馈与声音应用到六场，接入第二主射击的指定掉落和装配，统一六种 buff，优化现有 Boss，修复保存/重开/切场与旧档兼容。

### P2：准备申请展示证据

打包可运行版本；录制真实游戏声音的短视频与一次不使用保护/跳关的流程；保留迭代前后同场景对比；整理项目案例页、个人贡献和 AI 工具流程。

PPT/PDF 页面制作在证据稳定后进行，不以排版任务替代玩法打磨。

### 18.2 人工体验验收

用户先对同一片段盲看/盲玩少量版本，记录“启动是否跟手、能否连续切目标、命中是否有感、武器是否好听、F 是否能记住”。“动作更大”“平均帧率更高”“新增八个音效文件”都不独立构成通过。

随后找 3—5 名未参与开发的人短试玩，作为定性反馈，不把小样本包装成统计显著。重点观察能否理解 F、是否感到武器改变、是否主动用闪击、第一次死亡原因是否清楚，以及是否愿意再玩。

每轮反馈只选最影响体验的一两项处理，避免模型、镜头、速度、伤害和音效同时无记录地变动。

### 18.3 性能与稳定性

最终以明确测试机器、分辨率、画质和独立 Player 实测为准。建议默认 1080p、60fps 目标，同时记录平均、P95/P99 帧时间和卡顿事件。离屏渲染、模拟 30/60/120 帧输入与实际呈现帧率分开报告。

检查完整一局和数次重开，查看运行时异常、对象增长、声音堆积和旧引用。高面数模型是否需要 LOD 以实测为依据，不为了“工业化”预先重做全部美术。

### 18.4 每次交接固定记录

仓库/分支/提交；改动文件；实际构建路径；测试环境与方法；哪些通过/未通过/未测试；对应录像或日志；未提交改动；下一项唯一优先任务。

操作前后执行 Git 状态检查，不使用无差别 `git add .`，不自动覆盖/合并美术分支。没有推送就明确写没有推送。

## 19. 作品集组织建议

以下为展示建议，不是学校强制格式。

准备一段约 60—90 秒原声实机视频作为首要入口，配少量项目案例页与可运行包备份。案例页覆盖：问题与目标、核心循环、镜头/动作/声音的迭代、F 模块化装配、实现结构、测试证据和个人反思。页数可之后按申请系统要求调整。

作品集叙述区分：用户主导的体验目标、取舍和验收；AI 参与的代码/建模脚本/内容生成；项目实际使用的第三方或临摹资产；用户后续修改与集成。没有做过的动作制作、研究实验或原创资产不得写成独立完成。

FAZZ、机甲/武器参考与特效参考按事实注明。临摹或改造不能只靠改名就宣称完全原创。不需要为了这个问题此刻重做整机，但对外案例应突出自己的玩法、整合和验证贡献，保留来源与使用范围记录。

AI 工具使用可以作为方法论案例，不等于已经完成 AI 算法研究。申请不同专业时调整讲述侧重，不能为包装临时添加与核心体验无关的功能。

PolyU 2027 入学官方页列有作品集线上提交安排，并可能要求面试；具体格式等通知。官方 Early Round 为 2026-10-20，Main Round 为 2027-02-25，属于申请截止日期，不应擅自当成单独作品集提交日期。[S10] 雅思与申请材料仍有独立工作量，Demo 需要按上述停止条件收口。
